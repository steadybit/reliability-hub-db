# Introduction

Actively terminates matching TCP connections on the host by sending TCP RST responses. Unlike "Block Traffic", which silently drops packets causing timeouts, this attack causes immediate connection errors on the client side.

# Prerequisites

If you are not using our container images for the extension, the attack requires `iptables` (from the iptables package).

# Details

The attack uses iptables REJECT rules with `--reject-with tcp-reset` to send TCP RST packets for matching connections. This affects both incoming and outgoing TCP traffic. The iptables rules are inserted at the top of the host's filter chains to ensure they are evaluated before any existing rules (e.g., Kubernetes kube-proxy rules). Each attack instance creates a unique iptables chain, allowing multiple concurrent attacks with different filters on the same target.

Only TCP traffic is affected. UDP and other protocols are not impacted by this attack.

# L7 mode: reset by hostname (SNI / HTTP Host)

Enabling **Reset at L7 by hostname (SNI/Host)** switches this attack from the packet-level engine to the transparent proxy, so it resets connections to a *named dependency* instead of by IP/port. The default (checkbox off) keeps the historical packet-level behaviour described above.

| | Default (packet-level) | L7 mode |
|---|---|---|
| Selects by | IP / port | hostname (TLS SNI / HTTP Host) |
| Direction | incoming and outgoing | outgoing only |
| HTTPS / shared or rotating IPs | only if you know the IPs | matched by hostname, works over HTTPS |
| Percentage | — | supported |
| Statistics | — | per-hostname matched/faulted widget |

In L7 mode the **Hostnames** parameter is required (it selects the dependency), **Percentage** applies (per request for cleartext HTTP, per connection for HTTPS; see *Protocol compatibility (L7 mode)*), and an empty **Include Ports** intercepts every port, as in packet-level mode. **Exclude Hostnames** and **Network Interface** apply to packet-level mode only.

With **Include Ports** left empty in L7 mode, every outgoing TCP connection of the host passes through the proxy during the attack; localhost traffic is excluded unless **Attack Localhost Traffic (L7 mode)** is enabled (see below). This includes system services such as the kubelet and the container runtime. Only connections to the hostnames are reset, everything else is relayed untouched. Because TLS is recognized on any port by its SNI, other protocols over TLS whose SNI matches a hostname (e.g. Kafka or Redis over TLS) are reset too. Set **Include Ports** to `80,443` to limit the attack to the usual HTTP(S) ports.

## Protocol compatibility (L7 mode)

- **HTTP/1.x cleartext** — matched by the HTTP `Host` header. **Percentage** applies per request: requests are forwarded until one is selected, then the connection is reset; the client's next connection starts over.
- **HTTPS (TLS), HTTP/1.1 and HTTP/2 over TLS** — matched by the TLS SNI (the reset acts at the connection level). **Percentage** applies per connection, so with keep-alive clients the share of failing requests can be far from the configured Percentage.
- **HTTP/2 cleartext (h2c)** — not matched.
- **HTTP/3 (QUIC)** — not affected: the proxy intercepts TCP only.

## Statistics (L7 mode)

A **Dependency Fault Statistics** widget shows the intercepted ports, how many connections were intercepted, how many of them went to one of the hostnames and how many were reset, plus a per-hostname breakdown. Zero intercepted connections means the interception installed but no traffic hit it; intercepted connections but none to the hostnames means the hostnames don't match the TLS SNI or HTTP Host header. For cleartext HTTP, the summary shows requests instead of connections: how many went to one of the hostnames and how many were reset, with the share in percent to compare with **Percentage**. If the proxy can't connect to a destination, the widget shows how often forwarding failed.

## Localhost traffic (L7 mode)

By default, localhost traffic (`127.0.0.0/8`) on the host is never intercepted, whether or not *Include Ports* are set.
Enable **Attack Localhost Traffic (L7 mode)** to intercept it as well, e.g. when the application reaches the dependency through a local
forward proxy or a `127.x` entry in `/etc/hosts`.

- Matching localhost connections pass through the proxy: existing ones may be reset when the attack starts, and all
  of them are closed when it ends. Without *Include Ports*, this applies to **all** localhost traffic on the host, including local agents and sidecars.
  Use *Include Ports* to narrow it down.
- Only IPv4 localhost is intercepted; `::1` is not affected.
- If a hostname seems to point to localhost, the attack warns but still runs.
- The extension's own ports stay excluded, so the attack can still be stopped.
- Earlier versions intercepted localhost only when *Include Ports* were set.

# Use Cases

* Simulate abrupt connection resets from upstream or downstream services
* Test client-side retry and reconnection logic under immediate connection failures
* Verify circuit breaker behavior when connections are actively refused rather than timing out
* Simulate firewall or load balancer dropping connections with RST

# Parameters

| Parameter                          | Description                                                                                                                                              | Default |
|------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------|---------|
| Duration                           | How long should TCP connections be reset?                                                                                                                | 30s     |
| Include Hostnames                  | (optional) Restrict to/from which hosts the traffic is affected.                                                                                         |         |
| Include IPs/CIDRs                  | (optional) Restrict to/from which IP addresses or blocks the traffic is affected.                                                                        |         |
| Exclude Hostnames                  | (optional) Exclude traffic to/from these hosts from being affected. Excludes always take precedence over the include restrictions.                       |         |
| Exclude IPs/CIDRs                  | (optional) Exclude traffic to/from these IP addresses or CIDR blocks from being affected. Excludes always take precedence over the include restrictions. |         |
| Include Ports                      | (optional) Restrict to/from which ports the traffic is affected. Empty affects all ports.                                                                |         |
| Network Interface                  | (optional) Target network interface to affect. All non-loopback if none specified                                                                        |         |
| Attack Localhost Traffic (L7 mode) | (optional) L7 mode only: also intercept traffic to localhost (`127.0.0.0/8`). See *Localhost traffic (L7 mode)*.                                         | false   |
